# 第一轮扩展：训练预算 2500 / 4000 步的配对比较（2026-09-26）

在 1200 步之外新增 2500 与 4000 步两个预算，每个预算用 seeds 17/29/43 配对比较 E0（原始 GELU + 全参数衰减 0.1）与 E3（SwiGLU + LayerNorm/偏置不衰减）。其余设置与第一轮相同（batch 32、context 256、训练 FP32、评分 CPU FP32 四线程；2500/4000 的诊断间隔 500 步）。只用 validation，未评 test。12 个受保护文件的发布哈希与发布值一致。

本轮新增 12 个独立 run，全部从随机初始化训练，未从任何已有 checkpoint 续训；1200 步的 12 个 run 复用第一轮已冻结的结果。

| Max steps | Baseline 均值 ± 标准差 | Combined 均值 ± 标准差 | 配对 ΔBPB | 相对改善 |
|---:|---:|---:|---:|---:|
| 1200 | 2.074731 ± 0.003213 | 2.004174 ± 0.004746 | −0.070558 | 3.401% |
| 2500 | 1.868128 ± 0.005642 | 1.813965 ± 0.002717 | −0.054163 | 2.898% |
| 4000 | 1.774722 ± 0.006169 | 1.759765 ± 0.002139 | −0.014957 | 0.842% |

逐种子配对 ΔBPB（seeds 17 / 29 / 43）：1200 → −0.072382645 / −0.070418034 / −0.068872129；2500 → −0.058333351 / −0.059407965 / −0.044748810；4000 → −0.020020784 / −0.019222607 / −0.005626773。**9 个配对差值全部为负，方向一致，但幅度逐档下降。**

单样本 t 检验（df=2）：t = −69.46 / −11.48 / −3.20，双尾 p = 0.0002 / 0.0075 / 0.0852。三个种子只有 2 个自由度，p 值不足以作可靠的显著性判定；到 4000 步，差值均值已不足其自身标准差的 2 倍，在 5% 水平上不再能与种子噪声区分。Combined 的跨种子标准差在 2500（0.002717 对 0.005642）与 4000（0.002139 对 0.006169）都小于 Baseline。

**为什么 2500 与 4000 必须独立训练**：`train_round1.py` 的余弦周期按 `steps` 归一化，三个预算的学习率序列哈希互不相同（1200 `4f681cd4116fd480`、2500 `6265963bd912f44e`、4000 `e9c3d46bc8704f23`；峰值 9.8497e-04 / 9.9652e-04 / 9.9864e-04，末步都是 1.0000e-04）。第 1199 步的学习率分别为 1.00e-04、5.79e-04、8.15e-04。2500 与 4000 共享 500 步诊断网格，可直接测出同一 step 下的差距：Baseline 在 4000 配方下第 2500 步为 1.831881，比 2500 配方的 1.868128 好 **0.036248**（约为 2500 步基线跨种子标准差的 **6.4 倍**），原因是 2500 配方末段已退火到下限而几乎停止学习。把 4000 步 run 的第 2500 步当作 2500 步结果，会让 Baseline 显得好约 0.036 BPB，系统性低估 E3 的优势。

- 公平性：每个 budget + seed 的 E0/E3 训练目标数完全相同（2500 → 20,480,000；4000 → 32,768,000），训练窗口 / 学习率 / 诊断窗口哈希相同且被汇总脚本独立重算比对；审计 **299 项检查 0 失败**。1200 档重算的组均值与第一轮冻结报告逐位相同；训练中的 GPU 验证分与 CPU FP32 评分最大差 2.82e-08；单元测试 17/17 通过。
- 收敛：12 个新 run 的验证 BPB 全部单调下降（12/12），最佳步均等于末步（12/12），**未见过拟合，也未到平台期**——4000 步 Baseline 每 500 步仍改善约 0.0097 BPB，末区间/首区间为 0.007，是减速而非平台。训练子集与验证集 NLL 差在扩大，但两者来自不同文本样本，只有走向有解释意义。
- 结论符合"优势随预算缩小"：|ΔBPB| 0.070558 → 0.054163 → 0.014957，相对 1200 步保留 76.8% 与 21.2%，且缩小在**加速**。这支持把主要收益解释为**收敛速度 / 计算效率**的改善，而不是最终能力的提升；三个预算点不足以外推更长的预算会让优势归零、反转还是稳定。
- 成本：新增 12 个 run 共 **319,488,000** 个训练目标（2500 档 122,880,000；4000 档 196,608,000），纯 GPU 训练累计 **1892.6 秒**；加上第一轮的 117,964,800，三档合计 **437,452,800** 个训练目标。每 run 目标数 9,830,400 / 20,480,000 / 32,768,000，纯训练均值 35.6 / 114.6 / 200.9 秒。
- 资源：所有 run 的 CPU 评分进程树峰值工作集 ≤ **1.807 GiB**，训练进程树 ≤ **1.901 GiB**，PyTorch 峰值 GPU 分配约 0.539–0.587 GB，单 checkpoint 约 **5.2 MiB**（与预算无关，更长训练不增加推理资产）。三个资源门槛的最终判定仍需冻结方案下的完整 test 评测。
- 局限：预算差异不等于训练时长差异（每档是不同的完整学习率配方）；n=3；不能外推；所有预算都终止在峰值的 10%（1.0e-04）而非接近零；属近似等参数（E3 多 4,800，约 0.44%）而非等计算量比较；计时受机器负载与热状态影响（同配方 1200 轮 27.6 秒对 4000 轮 209.8 秒），跨批次不可比。
